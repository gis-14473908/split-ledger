# split-ledger 设计文档

日期：2026-10-25
状态：已确认（CSV 只预留接口）

## 1. 目标

一个给在英国留学的学生用的**手机网页记账应用**，币种为英镑（£）。核心是“导入账单 → 自动分类 → 逐笔确认是否和同学一起花 → 分账 → 面板显示每个人该转给我多少钱”。支持多用户注册。

**成功标准**

- 一批银行交易（截图或 CSV）导入后，能在几分钟内用滑卡方式全部处理完
- 面板上每个人的净欠款准确，和手算结果一致
- 同学注册并关联后，能看到自己欠谁多少钱、对应哪些账单

**用户已确认的需求**

| 需求 | 决定 |
|---|---|
| 币种 | 全部英镑。招商银行 VISA 在英国消费也是英镑，取“交易金额 GBP”，人民币入账金额只作参考保存 |
| 账单来源 | 银行 App 截图（AI 识别）；CSV 本期只预留接口，等有样本再补。银行：HSBC、Monzo、Lloyds、招商银行 |
| 分账方式 | 平均分；或按小票分（拍小票 → AI 识别商品 → 逐个商品选归属） |
| 分账对象 | 可以先随手写名字，同学注册后再通过邀请链接关联到他的账号 |
| AI 模型 | 可切换：默认 Claude Sonnet 5.5；可一键用 Opus 5.5 重新识别；设置里可改默认（Haiku 5.5 / Sonnet 5.5 / Opus 5.5） |
| 确认界面 | 方案 C：叠卡 + 上方手牌条，卡片附带帮助回忆的信息（见 §5.2） |
| 部署 | GitHub 仓库 `split-ledger`，前端 Vercel，后端 Supabase |
| 界面语言 | 中文 |

## 2. 架构

```
手机浏览器（Next.js 网页，PWA，可添加到主屏幕）
   │
   ├── Supabase：Auth（邮箱+密码）/ Postgres（RLS 隔离）/ Storage（私有桶存截图和小票）
   │
   └── Vercel 上的 Next.js Route Handlers（服务器端）
         ├── /api/ai/statement  银行截图 → 交易列表 + 分类
         ├── /api/ai/receipt    小票照片 → 商品列表
         └── Claude API（Anthropic TypeScript SDK，API Key 只在服务器端）
```

- **技术栈**：Next.js（App Router）+ TypeScript + Tailwind CSS；`@supabase/ssr`；`@anthropic-ai/sdk`；Vitest 单元测试；Playwright 端到端测试。
- **CSV 解析在浏览器里完成**，不调用 AI，也不上传原文件。
- **图片在浏览器端先压缩**（长边约 1600px、JPEG），再上传到 Supabase Storage 并发给识别接口，以控制费用和请求体大小。
- **金额一律以整数便士（pence）存储**，避免浮点误差；显示时再格式化为 £。

## 3. 数据模型

所有表都开启 Row Level Security。`owner_id` 指向 `auth.users`。

**profiles**：`id`（= auth user id）、`display_name`、`default_model`（`haiku` / `sonnet` / `opus`，默认 `sonnet`）、`created_at`

**contacts**（我的分账对象）：`id`、`owner_id`、`name`、`linked_user_id`（可空，关联后指向同学的账号）、`invite_token`（可空，唯一）、`created_at`

**transactions**：`id`、`owner_id`、`occurred_on`（日期）、`occurred_at_time`（可空）、`merchant_raw`（银行原始描述）、`merchant`（清洗后的商家名）、`location`（可空）、`amount_pence`（正数为支出）、`original_amount` + `original_currency`（可空，例如招商的 CNY 入账金额）、`category`、`bank`（`hsbc` / `monzo` / `lloyds` / `cmb` / `other`）、`source`（`screenshot` / `csv` / `manual`）、`status`（`pending` / `personal` / `shared` / `transfer` / `later`）、`ai_hint`（可空）、`dedupe_key`、`import_id`、`created_at`

**imports**：`id`、`owner_id`、`kind`（`screenshot` / `csv`）、`file_paths`、`model_used`、`created_at`

**receipts**：`id`、`transaction_id`、`image_path`、`total_pence`、`model_used`

**receipt_items**：`id`、`receipt_id`、`name`、`price_pence`、`includes_me`（布尔）、`contact_ids`（uuid 数组）。归属人数大于 1 时视为共享，在这些人之间平分

**splits**（每笔共享交易里每个人应承担的份额）：`id`、`transaction_id`、`contact_id`（为空表示“我”）、`share_pence`。约束：同一交易的所有份额之和 = 交易金额。

**settlements**（结清记录）：`id`、`owner_id`、`contact_id`、`amount_pence`（正数 = 对方付给我，负数 = 我付给对方）、`settled_on`、`note`

**分类（固定枚举）**：超市、餐饮外卖、交通、购物、房租水电、娱乐、医疗、转账（不计入消费）、其他。

### 3.1 欠款计算

对我和某个联系人 C：

```
C 欠我 = Σ 我的交易中分给 C 的份额
       − Σ C 的交易中分给“指向我的联系人”的份额（只有 C 已关联账号时才存在）
       − Σ 我和 C 之间的 settlements（对方付给我为正）
```

结果为正表示 C 欠我，为负表示我欠 C。四舍五入：平均分除不尽时，余下的便士给“我”（我不在分账人里时，给列表中的第一个人），保证份额之和等于总额。

计算放在一个纯 TypeScript 函数中（便于单元测试），同时用 Postgres 的 `security definer` 函数为面板提供数据。

### 3.2 权限（RLS）

- 交易、导入、小票、联系人、结清记录：只有 `owner_id = auth.uid()` 的人能读写。
- 关联的同学可以**只读**涉及自己的份额：通过一个 `security definer` 函数返回“别人账本里分给我的那些份额”，包含日期、商家、总额、我的份额，**不暴露**对方的其他交易。
- Storage 私有桶，路径为 `{user_id}/...`，策略只允许本人访问。

## 4. 导入

### 4.1 截图导入

1. 用户选择一张或多张银行 App 截图。
2. 浏览器压缩后上传到 Storage，调用 `/api/ai/statement`。
3. 服务器调用 Claude（用户的默认模型），使用结构化输出（JSON schema），返回：银行、每笔交易的日期、时间（如有）、商家原文、清洗后的商家名、地点（如有）、金额、币种、原币金额（如招商的 CNY）、建议分类、是否为转账或收入、可选的提示语（例如“金额偏大，可能是聚餐”）。
4. 结果进入**预览列表**：可改每个字段、删除某行；疑似重复（同一用户、同一天、同金额、商家名归一化后相同）的默认不勾选。
5. 确认后写入 `transactions`，状态为 `pending`；收入和转账为 `transfer`。

预览页提供“用 Opus 5.5 重新识别”按钮。

### 4.2 CSV 导入（本期只预留接口）

用户暂时拿不到各家银行的导出样本，所以**本期不写具体银行的解析器**，只把接口和流程搭好，等拿到样本后再按家补上：

- 定义解析器接口 `CsvParser { bank; detect(headers): boolean; parse(rows): ParsedTransaction[] }` 和一个注册表；`ParsedTransaction` 与截图识别的输出是同一个类型，所以后面的预览、去重、入库流程两边共用。
- 导入页保留“上传 CSV”入口：浏览器内用 CSV 库读成行，依次询问注册表里的解析器；没有解析器认领时提示“暂不支持这个格式，请先用截图导入”。本期注册表为空，所以所有 CSV 都会走这个提示。
- 预留 `/api/ai/categorize`：批量传入商家名和金额，返回分类（CSV 没有分类时用）。本期就实现，因为它不依赖样本。
- 招商银行没有方便的 CSV 导出，只走截图。

之后补解析器时，每家银行一个文件加一份打码样本作测试夹具。

## 5. 逐笔确认（方案 C）

### 5.1 交互

- 页面上方是**手牌条**：所有待处理交易排成一排小牌，显示商家和金额；当前这笔高亮；已处理的变灰并标“自己 / 一起 / 稍后”；点任意一张可跳过去，点已处理的可以放回队列重新选。
- 中间是**叠卡**，手势：
  - ← 左滑：只是我自己的 → `personal`
  - → 右滑：和别人一起 → 弹出分账面板
  - ↑ 上滑：稍后再说 → `later`，排到队尾
- 下方有同样含义的三个按钮，适合不想滑动时点按。
- 顶部有“撤销”，可以撤回上一步。
- 点分类标签可以直接改分类。

### 5.2 卡片上的信息

- 银行标签、星期 + 日期 + 时间（有时间时显示）
- 商家名 + 地点（有地点时显示）
- 金额 + 分类标签
- **提示条**：优先显示历史记录（“上次在这家：£18.20，和孙豪平分”，由数据库查询得到）；否则显示 AI 提示（“可能是聚餐”）；招商交易附带人民币入账金额
- **当天的消费**：当天所有交易按时间排列，当前这笔高亮

### 5.3 分账面板（右滑后从底部弹出，位于卡片之上）

- 选人：联系人多选；“我”默认选中，可取消（代付场景）；可以直接输入新名字创建联系人。
- 选方式：
  - **平均分**：实时预览每人金额。
  - **按小票分**：拍照或从相册选择小票 → `/api/ai/receipt` 识别商品 → 商品列表，每行点选归属（我 / 某人 / 多人共享）→ 显示每人小计。小票合计与银行金额不一致时，显示差额并让用户选：按比例分摊，或算在自己头上。
- 确认后写入 `splits`，交易状态改为 `shared`。

## 6. 面板（首页）

- **欠款区**：每个联系人的净额（“孙豪欠你 £23.40” / “你欠李明 £5.00”）。点进去看明细（相关交易和结清记录），可以点“已结清”录入一条 settlement（默认金额为当前净额，可修改）。
- **本月支出**：只算我自己承担的部分（个人消费 + 共享交易中我的份额），按分类展示条形图，支持切换月份。
- 待处理数量入口：“还有 6 笔待确认”。

## 7. 联系人与邀请

- 联系人可以只有名字。
- 在联系人详情里生成**邀请链接**（`/invite/{token}`）。同学打开后注册或登录，确认后 `linked_user_id` 设为他的账号，链接失效。
- 关联后，同学的面板里会出现“你欠 XX £…”，数据来自 §3.2 的只读函数；双方各自记的账自动互相抵消（§3.1）。

## 8. 设置

- 昵称
- 默认识别模型（Haiku 5.5 / Sonnet 5.5 / Opus 5.5），附带每种模型的大致单价说明
- 退出登录

## 9. AI 调用细节

- 使用 `@anthropic-ai/sdk`，模型 ID：`claude-sonnet-5-5`（默认）、`claude-opus-5-5`、`claude-haiku-5-5`。
- 用结构化输出（`output_config.format` + JSON schema）保证返回可解析；服务器端用 Zod 再校验一遍。
- Sonnet 5.5 和 Opus 5.5 开启服务端拒答回退（`fallbacks: "default"`），减少偶发拒答导致的识别失败。
- 每次调用记录所用模型，存入 `imports.model_used` / `receipts.model_used`。
- 只在服务器端读取 `ANTHROPIC_API_KEY`。接口要求用户已登录，并做简单的速率限制（例如每人每分钟 10 次），防止被滥用产生费用。

## 10. 错误处理

| 情况 | 处理 |
|---|---|
| 截图里识别不出交易 | 提示“没识别出交易，换一张更清楚的截图，或用 Opus 5.5 重试” |
| AI 返回格式不合法 | 服务器自动重试一次，仍失败则提示用户重试 |
| 小票合计 ≠ 银行金额 | 显示差额，用户选择按比例分摊或算自己的 |
| CSV 格式不支持（本期所有 CSV） | 提示“暂不支持这个格式，请先用截图导入” |
| 疑似重复交易 | 预览中默认不勾选，并标注“可能重复” |
| 网络或 Supabase 出错 | 顶部提示条；滑卡操作保存失败时卡片回到原位，可重试 |
| 邀请链接已使用或无效 | 提示“链接已失效，请让对方重新生成” |

## 11. 测试

- **单元测试（Vitest）**：欠款计算（平均分、余数分配、按小票分、共享商品、差额分摊、双向抵消、结清）；CSV 解析器注册表（空注册表时给出“暂不支持”）；去重键生成。
- **端到端测试（Playwright，手机视口）**：注册 → 截图导入（AI 返回固定值）→ 滑卡处理（左滑、右滑平均分、上滑）→ 面板金额正确 → 邀请链接关联第二个账号 → 第二个账号看到欠款。AI 接口在端到端测试中用固定返回值替代。
- **AI 冒烟测试**：几张示例截图和小票，手动运行，检查识别结果大致正确（会产生少量费用，不放进自动测试）。

## 12. 部署

1. 创建 GitHub 仓库 `split-ledger`。
2. 创建 Supabase 项目，通过 migration 建表、建 RLS 策略、建 Storage 桶。
3. 创建 Vercel 项目并连接 GitHub 仓库，`main` 分支自动部署到生产环境。
4. 环境变量：`NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_ANON_KEY`（Vercel）；`ANTHROPIC_API_KEY`（用户自己在 console.anthropic.com 申请，在 Vercel 后台填入）。
5. Supabase Auth 设置站点 URL 为 Vercel 域名。

**注意**：Supabase 免费项目长时间不活跃会暂停，需要在后台手动恢复；免费套餐的注册确认邮件有发送频率限制，同学集中注册时可能需要稍等。

## 13. 不在本期范围内

- 多币种记账（全部按英镑）
- 自动连接银行账户（Open Banking）
- 原生 App、推送通知
- 群组 / 多人共享账本（只做两人之间的欠款）
- 不平均的按比例或按份数分账（只有平均分和按小票分）
- 数据导出
